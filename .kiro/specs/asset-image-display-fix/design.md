# Asset Image Display Fix - Bugfix Design

## Overview

This bugfix addresses the issue where generated asset images display as black boxes in the Batch Review phase because the feedback-handler Lambda returns raw DynamoDB data with only `s3Key` and `thumbnailKey` fields, while the frontend expects `s3Url` and `thumbnailUrl` fields containing presigned URLs. The fix involves adding presigned URL generation to the `getSessionAssets` function, following the same pattern already implemented in the assets-handler Lambda.

## Glossary

- **Bug_Condition (C)**: The condition that triggers the bug - when the feedback-handler's getSessionAssets function returns assets without presigned URLs
- **Property (P)**: The desired behavior - assets should include `s3Url` and `thumbnailUrl` fields with valid presigned URLs
- **Preservation**: Existing feedback submission and history retrieval functionality that must remain unchanged
- **getSessionAssets**: The function in `lambdas/feedback-handler/index.js` that retrieves assets for the Batch Review phase
- **Presigned URL**: A time-limited URL generated by AWS SDK that allows temporary access to private S3 objects
- **s3Key**: The S3 object key path stored in DynamoDB (e.g., `raw/{batchId}/{assetId}.png`)
- **thumbnailKey**: The S3 object key path for thumbnails stored in DynamoDB (e.g., `thumbnails/{assetId}_thumb.jpg`)

## Bug Details

### Fault Condition

The bug manifests when the feedback-handler Lambda's `getSessionAssets` function retrieves assets from DynamoDB and returns them directly to the frontend without generating presigned URLs. The frontend expects `s3Url` or `thumbnailUrl` fields to render images, but receives only `s3Key` and `thumbnailKey` fields.

**Formal Specification:**
```
FUNCTION isBugCondition(asset)
  INPUT: asset of type DynamoDBAssetRecord
  OUTPUT: boolean
  
  RETURN (asset.s3Key IS NOT NULL OR asset.thumbnailKey IS NOT NULL)
         AND asset.s3Url IS NULL
         AND asset.thumbnailUrl IS NULL
         AND asset IS returned by getSessionAssets function
END FUNCTION
```

### Examples

- **Example 1**: Asset with s3Key `raw/batch-123/asset-456.png` is returned without `s3Url` field → Frontend displays black box
- **Example 2**: Asset with thumbnailKey `thumbnails/asset-789_thumb.jpg` is returned without `thumbnailUrl` field → Frontend displays black box
- **Example 3**: Asset with both s3Key and thumbnailKey is returned without either URL field → Frontend displays black box
- **Edge Case**: Asset with s3Key but no thumbnailKey should generate only `s3Url` field (thumbnailUrl can be null)

## Expected Behavior

### Preservation Requirements

**Unchanged Behaviors:**
- Feedback submission via `submitFeedback` function must continue to work exactly as before
- Feedback history retrieval via `getFeedbackHistory` function must continue to work exactly as before
- Session ownership verification logic must remain unchanged
- Batch lookup logic (including fallback to most recent batch) must remain unchanged
- DynamoDB query patterns for assets, batches, and sessions must remain unchanged

**Scope:**
All inputs that do NOT involve the `getSessionAssets` function should be completely unaffected by this fix. This includes:
- POST /api/v1/feedback/{sessionId} - Submit feedback endpoint
- GET /api/v1/feedback/{sessionId} - Get feedback history endpoint
- All PromptEngineerAgent invocation logic
- All DynamoDB write operations for feedback records

## Hypothesized Root Cause

Based on the bug description and code analysis, the root cause is clear:

1. **Missing URL Generation Logic**: The `getSessionAssets` function returns raw DynamoDB items without transforming `s3Key` and `thumbnailKey` fields into presigned URLs. The assets-handler Lambda already implements this pattern correctly using `@aws-sdk/s3-request-presigner`, but feedback-handler does not.

2. **Missing Import**: The feedback-handler Lambda does not import the `getSignedUrl` function from `@aws-sdk/s3-request-presigner` or the `GetObjectCommand` from `@aws-sdk/client-s3` (it's imported in shared but not used).

3. **Inconsistent Response Format**: The feedback-handler returns assets in a different format than the assets-handler, creating an inconsistent API contract. The frontend expects the same URL fields regardless of which endpoint provides the assets.

## Correctness Properties

Property 1: Fault Condition - Assets Include Presigned URLs

_For any_ asset retrieved by the getSessionAssets function where the asset has an `s3Key` or `thumbnailKey` field, the fixed function SHALL generate presigned URLs and include them as `s3Url` and `thumbnailUrl` fields in the response, enabling the frontend to display images correctly.

**Validates: Requirements 2.1, 2.2, 2.3**

Property 2: Preservation - Non-Asset Endpoints Unchanged

_For any_ request that does NOT target the getSessionAssets function (feedback submission, feedback history retrieval), the fixed code SHALL produce exactly the same behavior as the original code, preserving all existing feedback workflow functionality.

**Validates: Requirements 3.1, 3.2, 3.3, 3.4**

## Fix Implementation

### Changes Required

**File**: `lambdas/feedback-handler/index.js`

**Function**: `getSessionAssets`

**Specific Changes**:

1. **Add Import**: Import `getSignedUrl` from `@aws-sdk/s3-request-presigner` at the top of the file
   ```javascript
   const { getSignedUrl } = require('@aws-sdk/s3-request-presigner');
   const { GetObjectCommand } = require('@aws-sdk/client-s3');
   ```

2. **Transform Assets Array**: After retrieving assets from DynamoDB (line ~118), map over the assets array to generate presigned URLs for each asset

3. **Generate s3Url**: For each asset with an `s3Key`, call `getSignedUrl` with S3 GetObjectCommand to generate a presigned URL with 1-hour expiration

4. **Generate thumbnailUrl**: For each asset with a `thumbnailKey`, call `getSignedUrl` with S3 GetObjectCommand to generate a presigned URL with 1-hour expiration

5. **Handle Missing Keys Gracefully**: If `thumbnailKey` is null/undefined, set `thumbnailUrl` to null rather than attempting URL generation

6. **Return Transformed Assets**: Return the assets array with added `s3Url` and `thumbnailUrl` fields in the response object

**Implementation Pattern** (following assets-handler pattern):
```javascript
// After line 118: console.log('Assets found:', assetsRes.Items?.length || 0);

// Generate presigned URLs for each asset
const assetsWithUrls = await Promise.all(
  (assetsRes.Items || []).map(async (asset) => {
    try {
      // Generate presigned URL for the main image
      const s3Url = await getSignedUrl(
        s3,
        new GetObjectCommand({
          Bucket: process.env.S3_BUCKET,
          Key: asset.s3Key
        }),
        { expiresIn: 3600 } // 1 hour
      );

      // Generate presigned URL for thumbnail if exists
      let thumbnailUrl = null;
      if (asset.thumbnailKey) {
        thumbnailUrl = await getSignedUrl(
          s3,
          new GetObjectCommand({
            Bucket: process.env.S3_BUCKET,
            Key: asset.thumbnailKey
          }),
          { expiresIn: 3600 }
        );
      }

      return {
        ...asset,
        s3Url,
        thumbnailUrl
      };
    } catch (err) {
      console.error(`Failed to generate URL for asset ${asset.assetId}:`, err);
      return asset; // Return original asset if URL generation fails
    }
  })
);

return response(200, {
  session,
  batch: batchRes.Item,
  assets: assetsWithUrls, // Changed from assetsRes.Items
  totalAssets: assetsWithUrls.length
});
```

## Testing Strategy

### Validation Approach

The testing strategy follows a two-phase approach: first, surface counterexamples that demonstrate the bug on unfixed code, then verify the fix works correctly and preserves existing behavior.

### Exploratory Fault Condition Checking

**Goal**: Surface counterexamples that demonstrate the bug BEFORE implementing the fix. Confirm that assets are returned without presigned URLs.

**Test Plan**: Write tests that call the getSessionAssets endpoint and inspect the response structure. Run these tests on the UNFIXED code to observe that `s3Url` and `thumbnailUrl` fields are missing.

**Test Cases**:
1. **Basic Asset Retrieval Test**: Call GET /api/v1/feedback/{sessionId}/assets and verify response contains assets with only `s3Key` fields (will fail on unfixed code - no s3Url)
2. **Thumbnail Asset Test**: Verify assets with `thumbnailKey` are returned without `thumbnailUrl` field (will fail on unfixed code)
3. **Multiple Assets Test**: Verify batch with 10+ assets returns all without URL fields (will fail on unfixed code)
4. **No Thumbnail Test**: Verify asset with s3Key but no thumbnailKey is returned without any URL fields (will fail on unfixed code)

**Expected Counterexamples**:
- Assets returned with `s3Key: "raw/batch-123/asset-456.png"` but no `s3Url` field
- Assets returned with `thumbnailKey: "thumbnails/asset-789_thumb.jpg"` but no `thumbnailUrl` field
- Frontend displays black boxes because `asset.s3Url || asset.thumbnailUrl` evaluates to undefined

### Fix Checking

**Goal**: Verify that for all inputs where the bug condition holds, the fixed function produces the expected behavior.

**Pseudocode:**
```
FOR ALL asset WHERE isBugCondition(asset) DO
  result := getSessionAssets_fixed(sessionId)
  FOR EACH asset IN result.assets DO
    ASSERT asset.s3Url IS NOT NULL
    ASSERT asset.s3Url STARTS WITH "https://"
    ASSERT asset.s3Url CONTAINS asset.s3Key
    IF asset.thumbnailKey IS NOT NULL THEN
      ASSERT asset.thumbnailUrl IS NOT NULL
      ASSERT asset.thumbnailUrl STARTS WITH "https://"
    END IF
  END FOR
END FOR
```

### Preservation Checking

**Goal**: Verify that for all inputs where the bug condition does NOT hold, the fixed function produces the same result as the original function.

**Pseudocode:**
```
FOR ALL request WHERE request.path != "/assets" DO
  ASSERT submitFeedback_original(request) = submitFeedback_fixed(request)
  ASSERT getFeedbackHistory_original(request) = getFeedbackHistory_fixed(request)
END FOR
```

**Testing Approach**: Property-based testing is recommended for preservation checking because:
- It generates many test cases automatically across the input domain
- It catches edge cases that manual unit tests might miss
- It provides strong guarantees that behavior is unchanged for all non-asset-retrieval requests

**Test Plan**: Observe behavior on UNFIXED code first for feedback submission and history retrieval, then write property-based tests capturing that behavior.

**Test Cases**:
1. **Feedback Submission Preservation**: Observe that POST /api/v1/feedback/{sessionId} works correctly on unfixed code, then verify this continues after fix
2. **Feedback History Preservation**: Observe that GET /api/v1/feedback/{sessionId} works correctly on unfixed code, then verify this continues after fix
3. **Session Ownership Preservation**: Observe that 403 Forbidden responses work correctly for unauthorized users on unfixed code, then verify this continues after fix
4. **Agent Invocation Preservation**: Observe that PromptEngineerAgent is invoked correctly on unfixed code, then verify this continues after fix

### Unit Tests

- Test presigned URL generation for assets with s3Key
- Test presigned URL generation for assets with thumbnailKey
- Test graceful handling when thumbnailKey is null
- Test error handling when URL generation fails (should return original asset)
- Test that URL expiration is set to 3600 seconds (1 hour)
- Test that S3_BUCKET environment variable is used correctly

### Property-Based Tests

- Generate random asset records with various combinations of s3Key and thumbnailKey, verify all get appropriate URL fields
- Generate random session IDs and verify URL generation works for all valid sessions
- Generate random batch sizes (1-100 assets) and verify all assets get URLs
- Test that non-asset endpoints (feedback submission, history) produce identical results before and after fix

### Integration Tests

- Test full workflow: create session → generate batch → retrieve assets in Batch Review phase → verify images display
- Test that frontend can successfully load images using the generated presigned URLs
- Test that presigned URLs expire after 1 hour (verify 403 Forbidden after expiration)
- Test that assets without thumbnails still display using s3Url as fallback
